# KinoFlow Studio — Веб-интерфейс для генерации видео через ComfyUI API

Современное веб-приложение (React + TypeScript + Tailwind CSS) для генерации видео по тексту и референсным фотографиям персонажей (до 3 героев; первое фото используется как стартовый кадр I2V) через локальный сервер **ComfyUI** с поддержкой **Wan 2.2** и **CogVideoX**, а также встроенным улучшением промптов на базе **Gemini API**.

---

## 1. Запуск ComfyUI без ошибок CORS (обязательно)

По умолчанию браузер блокирует прямые HTTP- и WebSocket-запросы с веб-приложения к `http://127.0.0.1:8188` политикой CORS. Чтобы веб-интерфейс мог проверять статус (`/system_stats`), загружать референсные фото (`/upload/image`), ставить задачи в очередь (`/prompt`), отслеживать прогресс (`/ws`) и скачивать готовое видео (`/view`), запускайте ComfyUI с флагами `--listen` и `--enable-cors-header`.

### Windows (PowerShell / `.bat`)

```bat
@echo off
call venv\Scripts\activate.bat

python main.py ^
  --listen 0.0.0.0 ^
  --port 8188 ^
  --enable-cors-header "*" ^
  --reserve-vram 1.5 ^
  --fast fp16_accumulation
```

Если вы хотите разрешить доступ **только** с локального адреса веб-приложения (рекомендуется для безопасности):

```bat
python main.py --listen 127.0.0.1 --port 8188 --enable-cors-header "http://localhost:3000" --reserve-vram 1.5
```

### Linux / macOS / WSL2

```bash
source venv/bin/activate

python main.py \
  --listen 0.0.0.0 \
  --port 8188 \
  --enable-cors-header "*" \
  --reserve-vram 1.5 \
  --fast fp16_accumulation
```

### Пояснение ключевых флагов запуска ComfyUI

| Флаг | Назначение |
| :--- | :--- |
| `--listen 0.0.0.0` (или `127.0.0.1`) | Открывает API-сервер ComfyUI для входящих подключений (локальных или в локальной сети). |
| `--port 8188` | Порт ComfyUI по умолчанию (указывается в панели **Настройки подключения**). |
| `--enable-cors-header "*"` | Добавляет заголовок `Access-Control-Allow-Origin`, устраняя ошибки CORS в браузере при запросах к `/upload/image`, `/prompt`, `/history` и `/view`. |
| `--reserve-vram 1.5` | Резервирует 1.5 ГБ VRAM под активации и декодирование VAE (важно для видеокарт на 12 ГБ, например 2× RTX 4070). |
| `--fast fp16_accumulation` | Ускоряет вычисления диффузионных трансформеров (Wan 2.2) на GPU архитектуры Ada Lovelace (RTX 40xx). |

> **Важно про HTTPS / Mixed Content:** если веб-приложение открыто по `https://`, современные браузеры разрешают запросы к `http://127.0.0.1:8188` и `http://localhost:8188` как к loopback-адресу, но могут блокировать обращение к локальному LAN-IP (например, `http://192.168.1.50:8188`). В таком случае запускайте приложение локально на `http://localhost:3000` или настройте обратный прокси с TLS.

## 2. Требуемые кастомные ноды в ComfyUI

Шаблон `workflow_api.json` рассчитан на следующие популярные расширения ComfyUI:

1. **ComfyUI-GGUF** (`city96/ComfyUI-GGUF`) — загрузка квантованных моделей Wan 2.2 (`Q4_K_M`, `Q5_K_M`) и UMT5-XXL.
2. **ComfyUI-VideoHelperSuite** (`Kosinkadink/ComfyUI-VideoHelperSuite`) — нода `VHS_VideoCombine` для сохранения итогового `.mp4`.
3. *(не требуется)* Wan 2.2 не поддерживает IP-Adapter / FaceID, поэтому нод для референсов лиц в графах нет. Идентичность держится за счёт стартового кадра и передачи последнего кадра между сегментами.

## 3. Структура проекта и настройка `workflow_api.json`

- `workflow_api.json` — базовый API-шаблон графа ComfyUI с комментариями в `_meta.comment`, показывающими, в какие узлы подставляются:
  - **Ноды `1`, `2`**: выбранная видеомодель (High-Noise / Low-Noise для Wan 2.2 MoE или основная модель CogVideoX).
  - **Ноды `5`, `6`**: положительный и негативный промпты.
  - **Нода `30`**: разрешение (`width`, `height`) и длительность в кадрах (`length`).
  - **Ноды `40`, `41`**: `steps`, `noise_seed` (Seed) и точка переключения MoE-экспертов.
  - **Нода `60`**: экспорт `.mp4` (`VHS_VideoCombine`).
- `src/services/comfyService.ts` — модульный сервис для взаимодействия с API ComfyUI (`/system_stats`, `/upload/image`, `/prompt`, `/ws`, `/history`, `/view`, `/interrupt`).
- `server.ts` — серверная часть Express с маршрутом `POST /api/enhance-prompt`, который вызывает Gemini API через переменную окружения `process.env.GEMINI_API_KEY`.

## 4. Локальный запуск веб-приложения

1. Установите зависимости:
   ```bash
   npm install
   ```
2. Задайте ключ Gemini API в `.env` (см. `.env.example`):
   ```env
   GEMINI_API_KEY="ваш_ключ_gemini"
   ```
3. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
4. Откройте в браузере `http://localhost:3000`.

## 5. Обновление приложения

В шапке приложения (Electron-версия) показана текущая версия, например `v1.1.0`. При запуске и раз в 6 часов приложение проверяет последний релиз на GitHub (`vovik06302-ai/KinoFlow-Studio`). Если вышла более новая версия, появляется кнопка **«Обновить до vX.Y.Z»**. При нажатии установщик скачивается со шкалой и процентами, затем запускается, а приложение закрывается. Пока идёт генерация видео, кнопка неактивна. Клик по номеру версии запускает проверку вручную.

Как выпустить обновление:

1. Поднимите `version` в `package.json` (например, `1.1.2`).
2. Закоммитьте и отправьте изменения в ветку `main`: `git add -A && git commit -m "v1.1.2" && git push`.
3. GitHub Actions автоматически соберёт установщик и создаст (или обновит) GitHub Release `v1.1.2` с прикреплённым `.exe` (создавать тег вручную необязательно). После этого у пользователей появится кнопка **«Обновить до v1.1.2»**.

Репозиторий должен быть публичным, иначе проверка обновлений не увидит релизы.

## 6. Возможности версии 1.2.0

- **Проверка ComfyUI перед запуском.** Перед генерацией приложение через `/object_info` проверяет, что установлены все нужные ноды (`UnetLoaderGGUF`, `VHS_VideoCombine`, `RIFE VFI` и др.) и файлы моделей. Если чего-то не хватает, показывается список с папкой для каждого файла и ссылкой на пакет нод. Файлы из каталога можно скачать на вкладке «Модели и установка».
- **Исправлена скорость при RIFE.** RIFE всегда удваивает число кадров, а частота видео на выходе теперь равна `fps × 2` (16 → 32 fps). Раньше ролик шёл в замедленной съёмке.
- **Раскадровка и камера.** При длительности от 10 секунд можно описать действие в каждом 5-секундном сегменте и выбрать движение камеры (наезд, отъезд, панорама, облёт, следование, статика). Общее описание сцены сверху задаёт место, героев и стиль.
- **Склейка в один MP4.** В Windows-приложении кнопка «Склеить и скачать» использует FFmpeg: лишний первый кадр на стыках убирается, качество не теряется. FFmpeg ищется в `PATH`, в `C:\ffmpeg\bin` и в переменной `FFMPEG_PATH`. Без FFmpeg работает прежняя встроенная склейка (медленнее и с потерей качества).
- **Запуск ComfyUI из приложения.** Кнопка «Запустить ComfyUI» запускает `run_nvidia_gpu.bat` из папки, указанной на вкладке «Модели и установка», показывает журнал и сама проверяет подключение. При закрытии приложения запущенный ComfyUI останавливается.
- **Второй экземпляр ComfyUI на второй видеокарте.** В Windows-приложении можно независимо запускать два экземпляра ComfyUI Portable: «Экземпляр 1» (по умолчанию GPU 0, порт `8188`) и «Экземпляр 2» (по умолчанию GPU 1, порт `8189`), переключаясь на второй сервер кнопкой **«8189 · Вторая карта»** в блоке адреса сервера. Оба экземпляра запускаются напрямую через `python_embeded\python.exe` с аргументами `--cuda-device` и `--port`, а вывод stdout/stderr записывается в файлы журнала `<userData>/logs/comfyui-1.log` и `<userData>/logs/comfyui-2.log` без использования pipe-буферов консоли Windows.
- **Пресеты сцен.** Экспорт и импорт JSON с описанием, раскадровкой, камерой и основными настройками. Адрес сервера, папки, seed и изображения в файл не попадают.
- **Горячие клавиши.** `Ctrl+Enter` запускает генерацию, `Пробел` включает и ставит на паузу предпросмотр.
- **Фирменная иконка** для установщика, ярлыков и окна.

Фото персонажей: Wan 2.2 не поддерживает IP-Adapter, поэтому первое фото используется как стартовый кадр (режим I2V), если стартовый кадр не задан.
